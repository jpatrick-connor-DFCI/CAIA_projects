# COMPASS survival analysis — code review findings

Severity-ranked findings from the end-to-end review scoped in `REVIEW_PLAN.md`. Three
findings (1, 3, 7) were fixed and committed during this review; the other seven are
reported for a human decision, per the plan's triage rule (Stage 4): **FIX** requires an
explicit documented-contract violation with a uniquely-determined correct behavior and a
synthetic red/green test; **REPORT** covers anything that changes a published number's
*definition*, has more than one defensible answer, needs a cluster re-run to validate, or
is a scope decision.

Baseline and final test tally (unchanged across this review phase — no source was
touched beyond the three authorized fixes below): `python3 -m pytest -q` →
**2 failed, 109 passed**. The 2 failures are pre-existing and unrelated to survival code
(`COMPASS/data_preprocessing/tests/test_mixed_date_parsing.py`, `MM/DD/YYYY` parsing —
see the note under Finding 1's neighbors in Stage 0 of the plan; not touched here).

**Open question resolution — Finding 10 (`min_genomic_prevalence` intentional or omission?):**
No commit message, docstring, or README passage anywhere in the repo addresses why COMPASS's
`cox_aggregated.py` never supplies a concrete `min_genomic_prevalence` while IPIO's sibling
file does (with a named `DEFAULT_MIN_GENOMIC_PREVALENCE = 0.025` applied at three call sites).
The parameter's presence in COMPASS's function signatures (unused) strongly suggests it was

confirmed with certainty from available evidence (no test, comment, or doc states "COMPASS
intentionally applies no genomic prevalence floor"). **Verdict: likely omission, not provably
so — flag for the pipeline owner to confirm rather than silently applying IPIO's default.**
